# 焊缝缺陷数据集自增模板（5 类）

> 适用：在现有 `weld_train.py` 多源合并架构下，自行新增焊接缺陷数据并重训。
> 核心思路：脚本会扫描 `raw_mine/`（你新建的源目录）→ 递归配对图片/标注 → 按 `classes.txt` 映射 → 并入统一的 5 类 YOLO 数据集 → 训练。你只需"放对目录 + 标对格式 + 改 2 处脚本 + 重跑"。

---

## 一、5 类缺陷定义（标注时严格对照）

| id | 英文名 | 中文 | 说明 |
|----|--------|------|------|
| 0 | porosity | 气孔 | 焊接气孔 |
| 1 | crack | 裂纹 | 焊接裂纹 |
| 2 | undercut | 咬边 | 焊缝边缘母材的凹陷 |
| 3 | overlap | 焊瘤 / 过高 | 多余焊缝金属（excess reinforcement） |
| 4 | unfused | 未熔合 | 未熔合 / 未焊透（lack of fusion / penetration） |

⚠️ **只标这 5 类**。图里若出现夹渣(slag)、飞溅(spatter)等其他缺陷，**不要标**——脚本对不在 5 类内的框会自动忽略，不会报错。

---

## 二、目录结构（照抄）

在 AI Studio 的 `/home/aistudio/work/` 下新建 `raw_mine/`：

```
raw_mine/
├── classes.txt          # 必须，5 行，顺序固定（见第三节）
├── images/              # 放原图（jpg/png/bmp），可再分子文件夹
│   ├── weld_001.jpg
│   └── weld_002.png
└── labels/              # 放标注，文件名与图片同名（去扩展名）
    ├── weld_001.txt
    └── weld_002.txt
```

> - 图片与标注靠"**同名（不含扩展名）**"配对；子文件夹随意，脚本会递归扫描。
> - 没有标注框的图片会被跳过，不会进数据集。

## 三、classes.txt（直接复制）

```
porosity
crack
undercut
overlap
unfused
```

> 顺序就是上面表格的 id 顺序（0→4）。脚本靠它把标注里的 class_id 翻译成 5 类目标名。

## 四、标注文件格式（YOLO txt，首选）

每个 `.txt` 一行一个框：

```
<class_id> <cx> <cy> <w> <h>
```

- `class_id`：0=porosity, 1=crack, 2=undercut, 3=overlap, 4=unfused
- `cx, cy`：框**中心**坐标，除以图片宽/高，归一化到 0~1
- `w, h`：框宽高，同样归一化到 0~1

**示例**（一张图里有 1 个气孔 + 1 个咬边）：

```
0 0.512 0.430 0.120 0.090
2 0.300 0.880 0.200 0.040
```

**坐标换算（像素 → 归一化）**：

```
cx = (x_min + x_max) / 2 / img_width
cy = (y_min + y_max) / 2 / img_height
w  = (x_max - x_min) / img_width
h  = (y_max - y_min) / img_height
```

### 标注工具推荐
- **labelImg**（输出 YOLO txt，开箱即用）
- **makesense.ai**（网页免费，导出 YOLO）
- **Roboflow Annotate**（导出 YOLO，但国内需代理）

### VOC xml 也支持（可选）
若用 labelImg 默认存成 PascalVOC xml，脚本 `parse_voc` 会自动解析 `<name>porosity</name>` 这类标签，无需手动转。结构与上面一致，只是标注载体换成 xml。

## 五、把你的数据接入训练脚本（改 2 处）

打开 `ml/weld_train.py`：

**1) 在 `SOURCE_NAMES` 字典里加一行**（与现有 `'huangyebiaoke'` 等并列）：

```python
SOURCE_NAMES = {
    ...
    'mine': ['porosity', 'crack', 'undercut', 'overlap', 'unfused'],
}
```

**2) 在 `SOURCES` 列表里加一项**（放在现有源后面）：

```python
SOURCES = [
    ...
    {'root': 'raw_mine', 'key': 'mine', 'needs': None},   # 你的自建数据
]
```

> REMAP 里这 5 个英文名已是 1:1 映射（如 `'crack':'crack'`），**无需再改 REMAP**。
> 若 `raw_mine/` 不存在，脚本只会打印 `[跳过] 数据源 mine 目录 raw_mine 不存在`，不影响其他源训练。

---

## 六、运行（加数据后必须重建数据集）

1. 把整理好的 `raw_mine/` 上传到 AI Studio 的 `/home/aistudio/work/`。
2. 确保 `weld_train.py` 已含第五节的两处改动，并上传覆盖。
3. 新建 cell 运行：

```
%run /home/aistudio/work/weld_train.py --fresh
```

- `--fresh` 会清掉旧 `runs/`，用**全部源（含你的 raw_mine）**重新合并数据集，并**从头训满 120 轮增强版**。
- 控制台会打印 `[合并] mine: 保留图-标对 N` → 确认你的数据被读到。
- 合并结束后打印 `各类框数: {...}`，据此判断哪类还偏少。
- 若只想在已有模型上"继续吃新数据"而不重头训，去掉 `--fresh` 直接续训也行（数据集每次都会重新合并，新数据会进训练集）；但**加量后建议用 `--fresh` 干净重训**，避免旧 epoch 状态干扰。

> 数据集切分是**确定性**的：`md5(文件名)%5==0` 进验证集（约 20%），其余进训练集，不随机、可复现。

---

## 七、每类建议样本量（路线 A 已含增强，但仍建议）

- 多数类（porosity / overlap / unfused）：≥ 150 张图 / ≥ 300 框
- 少数类（**crack / undercut**，重点）：尽量多，≥ 100 张图 / ≥ 200 框。脚本会自动过采样 ×1.5 + `copy_paste=0.45` 补强，但原始样本越多越稳。
- **标注质量 > 数量**：框要贴边、不漏标；一张图里多个同类缺陷要分别标。

---

## 八、验收与导出（同主流程）

- 验收线：porosity mAP50 ≥ 0.85；crack / undercut **recall ≥ 0.9**。
- 跑满 120 轮后脚本自动 `val` + 导出 `WeldDefectModel.mlpackage`（带 NMS）。
- 后续按主流程把新 `mlpackage` 下载、覆盖 `app_ios/native/WeldFatigueChecker/WeldDefectModel.mlpackage/`（类名顺序不变，不改代码）。

---

## 九、快速检查清单（每次加数据前过一遍）

- [ ] 每个有缺陷的图都有同名 `.txt`（或 `.xml`）
- [ ] class_id 用 0~4，且只对应 5 类
- [ ] 坐标已归一化到 0~1（无超界、无负数）
- [ ] `weld_train.py` 已加 `SOURCE_NAMES['mine']` 与 `SOURCES` 两项
- [ ] 运行用 `--fresh`，并看到 `[合并] mine: 保留图-标对 N`
- [ ] 核对 `各类框数` 后决定是否继续补某类
